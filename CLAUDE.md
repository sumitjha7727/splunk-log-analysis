# Standing rules for this repo

Applies to every project in this repo, including `detection-lab/`. These aren't preferences — they're the constraints this repo's credibility depends on, and they came out of real mistakes (or near-mistakes) caught during the Phase A/B pass that added `07-detection-as-code`'s search-window fix, the DNS tunneling investigation, `splunk-app/`, and `detection-lab/`.

1. **Never fabricate query output, entropy values, event counts, or any other figure that can only come from actually running something.** Where a step needs live Splunk output, a live campaign run, or a GUI change, write it into `RUNBOOK.md` (or, for `detection-lab`, a campaign manifest) as a numbered action with a `RESULTS: <pending>` placeholder — never as an invented number standing in for one.
2. **Index is always pinned, never `index=*`.** Every SPL query in this repo, in any project, uses an explicit index name. `index=*` rescans everything on every run and has already caused one real bug (Project 7's original hourly alerts re-matching the same static events forever) — it doesn't get reintroduced.
3. **A scheduled alert's search window must match its rule's declared timespan.** If a Sigma correlation rule declares `timespan: 1h`, the SPL alert implementing it runs on a matching relative window (`earliest=-1h latest=now`), not `earliest=0`. An unscheduled, undocumented-as-live query may keep `earliest=0` — but only with an explicit note explaining why no schedule exists for it to match, never silently.
4. **Parsing and alert configuration live in `splunk-app/`, never only in markdown or the GUI.** Field extractions, index/sourcetype definitions, line-breaking fixes, and saved-search/alert definitions belong in `.conf` files under a `splunk-app/default/` directory, versioned in this repo. A markdown writeup can *document* a field extraction or an alert; it is never the only place that extraction or alert is defined.
